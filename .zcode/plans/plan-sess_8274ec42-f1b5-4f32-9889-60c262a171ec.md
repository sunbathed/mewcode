## 目标

把当前“逐行 input/print”的交互改成模板所示的**单个全屏终端界面**，不是打开新的图形窗口。运行 `python -m mewcode` 后，当前终端被 TUI 接管：上方显示对话记录，中间/下方是输入框，底部显示会话、模型和连接状态。

## 视觉结构

- 顶部：MewCode 标题、版本和当前会话信息。
- 主区域：可滚动对话区，区分用户消息、模型消息和系统提示；模型流式输出时实时追加到当前回答。
- 输入区域：固定在底部，用户输入问题或斜杠命令后按 Enter 提交。
- 状态栏：显示当前会话 ID、当前模型、连接状态和可用命令提示。
- 深色终端风格：使用 Textual 的 CSS，适配 Windows PowerShell、PyCharm Terminal 和普通终端。

## 技术方案

1. 在 `pyproject.toml` 增加 `textual` 运行依赖。
2. 新增 `src/mewcode/tui.py`，定义 Textual 应用、布局和消息组件。
3. 保留 `config.py`、`session.py`、`storage.py`、`llm_client.py`、`commands.py` 的业务接口，不重复实现 LLM 请求或会话逻辑。
4. 将当前 `App._ask()` 的请求消费逻辑改造成可被 TUI 调用的异步任务：
   - 提交问题后立即在对话区显示用户消息；
   - 通过 `asyncio`/Textual worker 消费 `TextDelta`；
   - 每个增量实时更新模型回答组件；
   - 结束后保存 assistant 消息；
   - 流式中断保留已收到内容并显示提示；
   - 普通 LLM 错误显示提示并按现有规则回滚未完成请求。
5. 斜杠命令继续复用 `parse_command()`：
   - `/new` 新建会话；
   - `/sessions` 在对话区显示列表；
   - `/use <id>` 切换会话并刷新对话区；
   - `/clear` 清空当前对话显示和上下文；
   - `/exit` 保存并退出 TUI。
6. 启动入口改为启动 TUI；保留现有测试所需的可注入 App/假客户端接口，避免破坏已有单元测试。
