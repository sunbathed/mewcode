# 任务

以一个全新的审查视角审查当前代码变更，不受前面对话影响。

## 审查维度

按以下五个维度审查代码变更：

1. **逻辑正确性**：边界条件、错误处理、竞态条件
2. **安全性**：注入风险、敏感信息泄露、权限问题
3. **性能**：不必要的重复计算、低效算法、资源泄漏
4. **代码风格**：一致性、命名、可读性
5. **可维护性**：职责划分、抽象层次、扩展性

## 报告格式

按严重程度分级报告：

- **Critical**：必须修复的问题
- **Warning**：建议修复的问题
- **Info**：可以改进的地方

代码质量好时给出正面反馈，避免只挑毛病。

## 输出

- 先运行 `git diff` 查看变更（仅分析当前 diff）
- 逐项给出发现：文件、行号（如果可定位）、问题描述、修复建议
- 最后给一个总体评价

$ARGUMENTS

如果没有指定审查范围，审查 `git diff` 的所有变更。
